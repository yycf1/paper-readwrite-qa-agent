# M1 开发笔记 · 检索下载与文献库账本

## 交付物

- `models.py`：Paper 统一模型（`source_id` 全局键）+ 标题归一化 + 跨源合并；
- `library.py`：library.db 账本（SQLite），五态生命周期 + DOI/归一化标题两级去重 + 片段模糊查找；
- `sources/`：OpenAlex（主力索引）、Europe PMC（生物医学）、arXiv（适配器保留）；每源 `search` + `probe`，网络异常统一包装 `SourceUnavailable`；
- `download.py`：多候选 PDF 地址依次尝试，`%PDF` 魔数校验；
- CLI：`search` / `download` / `status`，doctor 增加逐源连通检查；
- config.yaml 新增 `proxy` 与 `sources` 配置节。

## 关键决策与踩坑

1. **`_http.py` 丢包装事故**：初版 `http_get` 忘了把 `requests.RequestException` 包装成 `SourceUnavailable`，arXiv 连接重置(10054)直接冒泡崩掉 doctor。教训：**「统一异常包装」这类横切约定要写在调用方看不见的 helper 里时，必须有测试覆盖失败路径**（已补思路，M2 加网络失败注入测试）。
2. **OpenAlex 摘要是倒排索引**（词→位置列表），需按位置重建，`rebuild_abstract` 抽成纯函数便于离线测试。
3. **闭源会议论文的常态**：OpenAlex 前 4 篇经典 GNN 论文（ACM/Elsevier）都无直接 OA pdf_url，标记「仅摘要」；ACM 的 pdf 链接即使有也 403 反爬。对 CS 主题，arXiv 代理的优先级因此更高——无代理时 OA 命中率明显下降。
4. **Windows 侧**：`safe_dirname` 把 `source_id` 里的 `:` 换成 `_`（盘符保留字符）；控制台管道下 rich 输出走 cp936，`findstr` 中文匹配不可靠，验证脚本用 Python 读管道。
5. **去重两级键**：DOI 优先（精确），归一化标题兜底（`[\W_]`→空格 + lower）；EuropePMC 无 pmcid 时用 `source:id` 兜底构造 source_id。

## 遗留与观察

- 硅基流动账户 402 余额不足（后来发现免费模型也要求正余额）——不阻塞 M1，但 M2 LLM 提取前用户需充值或切换智谱 Key；
- arXiv 代理待用户提供端口；接通后 CS 论文 OA 命中率会显著提升；
- OpenAlex 的 oa_url 有时指向落地页而非 PDF，由下载器魔数校验兜底，代价是多一次失败请求，可接受。
