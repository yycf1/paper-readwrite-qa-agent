# M8 开发笔记 · Web 界面（React + TypeScript）

用户不可能一直在黑窗口里用产品。M8 在 M7 的 REST API 上落了图形界面：
Vite + React 19 + TypeScript，产物由 `pa serve` 同端口托管——部署面只剩
一条命令 `pa serve`。

## 页面结构

两个页签：
- **文献库**：检索框（调 /api/search，含年份条件）/ 状态 chips 过滤 +
  标题作者 DOI 筛选 / 论文表格 / 右侧详情面板（元数据、精读报告、实验结构
  结构化渲染、全文、摘要，Tab 切换）/ 一键处理按钮（下载→解析→提取→索引，
  后台任务 + 步骤进度展示）；
- **助手**：对话界面（调 /api/chat），意图理解回显、过程警告、新入库论文
  卡片（点击跳详情）、问答带出处（点击出处跳对应论文详情）。

URL 深链：`?paper=<id>` 直开详情、`?tab=chat` 直开助手（可分享、可回退），
前端用 history.replaceState 维护。

## 开发/部署形态

- 开发：`pa serve`（8000）+ `npm run dev`（Vite 5173，/api 代理转发）；
- 生产：`npm run build` → `web/dist` → FastAPI StaticFiles(html=True) 托管，
  同源无 CORS 问题。dist 提交进仓库（node_modules 不提交），clone 后无需
  node 环境即可 `pa serve` 出界面。

## 视觉测试抓到的真 bug

无头浏览器截图验收时发现详情页实验结构渲染成 `[object Object]`：
experiment.json 的 method 字段是嵌套对象、datasets/steps 是对象数组
（LLM 按 schema 输出了更丰富的结构），前端首版只处理了字符串/字符串数组。
教训：**不要相信「schema 说它是 string 数组它就一定是」**——normalize
schema 是宽松的，展示层必须递归渲染任意嵌套。修复后对象展开为
`键: 值` 片段、数组转列表、空值统一显示 —。

同一轮测试还确认：空库空态引导、处理进度步骤条、错误横幅、路由深链
全部正常；API 层 500 错误以红色横幅展示而非白屏。

## 其它踩坑

- Windows cmd 下 `timeout /t` 在无 stdin 环境不可用（「不支持输入重定向」），
  改 `ping -n N 127.0.0.1 >nul` 代替 sleep；
- Vite 产物文件名带内容哈希，改代码后 old hash 的 JS 仍是 200——验收截图
  前必须先 `npm run build` 再刷新；
- 8000 端口被占（winerror 10048）时 `pa serve` 报 bind error 退出，换端口
  即可；后续可考虑默认端口冲突提示。
