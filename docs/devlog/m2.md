# M2 开发笔记 · 解析、本地导入与知识提取

## 交付物

- `parsing/`：PDF（PyMuPDF，行级启发式分节 + 参考文献剥离 + 页锚点）、DOCX（Word 标题样式 → Markdown）、统一入口按扩展名分发；
- `llm.py`：OpenAI 兼容客户端，返回 (文本, token用量)；`parse_json_reply` 兼容围栏/夹杂文本；
- `extraction/experiment_flow.py`：experiment.json 提取——逐字段 confidence、unverified_claims、复现资产（LLM + 正则并集）；
- `extraction/report.py`：精读报告（六节结构，含可复现性备注）+ 代码围栏剥离；
- CLI：`pa add`（本地导入，内容哈希幂等）、`pa parse`、`pa analyze`（缺 Key 明确报错、未解析自动补跑）。

## 关键决策与踩坑

1. **LLM 输出的 JSON 不可全信但可约束**：prompt 给固定 schema + "未说明则留空 + unverified_claims"，实测 DeepSeek-V3 遵守良好；`normalize_experiment` 再做兜底（缺失字段补空、类型校验），双层防护。
2. **报告被包进 ```markdown 围栏**：LLM 偶发把整份 Markdown 当代码块输出，`strip_code_fence` 生成时剥离 + 已生成文件清洗。教训：**所有 LLM 自由文本产物都要过一道「展示层消毒」**。
3. **空结果守卫要按格式区分**：PDF 200 字符阈值（防扫描版）误杀了合法的短 DOCX，改为 DOCX 30 字符。守卫规则应当跟「该格式的失败模式」对齐。
4. **python-docx 的 `add_heading(level=0)` 产生 Title 样式**而非 Heading 0，`style.name == "title"` 要单独处理。
5. **URL 正则会吃到句尾标点**（"...bar." 尾点属于句子），统一 rstrip。
6. **复杂度教训**：`normalize_experiment` 初版默认值表达式写成了难以阅读的绕圈嵌套（生成时自我纠缠），重写为 dict comprehension 后 5 行清晰——LLM 生成复杂表达式时优先拆平。

## 遗留与观察

- 双栏 PDF 的行序（sort=True 近似阅读顺序）在复杂版式下可能串行——实测这篇单栏没问题，双栏论文待更多样本验证；效果不足时按 PLAN 引入 MinerU；
- analyze 的耗时提示只有 ⏳ 行，长论文 30s+ 无进度反馈，M4 可考虑流式或分段提示；
- `pa download --all` 串行下载较慢，M3/M4 可加有限并发（对源友好前提下 2~3 并发）。
