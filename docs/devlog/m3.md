## 关键决策与踩坑

1. **分块上限 bug**：emit 后的重叠尾（carry）叠加下一个满尺寸块时没有再校验，最大可超出 overlap 长度（实测出现 890 token 块）。修复为装不下就放弃重叠。教训：**「上限约束」要在每个拼接点重新验证，而不是只在单点校验**。
2. **章节名被双栏 PDF 污染**：`2 Related Workoverall preferences…` 这类标题与正文粘连行，解析层收紧编号标题判定（≤10 词 → ≤6 词），分块层再压空格限长 48 字符兜底。**两层各自防一道，比单层启发式更稳**。
3. **k=5 → k=8 不是调参凑分**：诊断显示未命中 case 的期望事实都真实排在 6~8 位（距离 0.49~0.52 vs 首位 0.40），是检索粒度问题不是召回失败；块均 600 token 时 8 块 ≈ 5k token 上下文，成本可忽略。先用诊断确认失败模式，再改配置。
4. **评测集是基准真值，必须回原文核验**：初稿从 experiment.json（LLM 产物）取事实，核验发现 λ=0.2/τ=0.1 等在解析文本中根本不存在（PDF 希腊字符提取缺失）——直接拿来出题会测出一堆「假未命中」。所有事实改为 grep 原文通过后才写入。
5. **仅摘要论文的索引语义**：摘要单块入库但**不推进状态机**（保持 discovered/download_failed），这样下载重试逻辑不受影响，后续拿到全文可无缝升级为全文索引。状态机表达「全文生命周期」，索引覆盖度由向量库自行记录（metadata.mode）。
6. **Chroma 增量**：不做逐块 diff，按论文整体「删旧插新」——块数少（百级）、语义简单（一篇一个版本）、天然幂等。评测集 schema 也进了单测（防手写漂移）。
