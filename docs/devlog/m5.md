## 本里程碑最重要的发现：推理模型的 thinking 吃 tokens

**现象**：GLM-4.7-Flash 在简单任务（查询优化）上返回**空 content 但 completion=200**（正好等于 max_tokens）。
**根因**：GLM-4.7 是混合推理模型——思考过程消耗 completion tokens 预算，max_tokens 太小时思考没结束就被截断，正文零输出。
**修复**：`llm.chat` 增加 `thinking` 参数（`extra_body={"thinking": {"type": "disabled"}}`）。原则：
- **简单确定性任务（分类/改写/打分）必须禁用思考**——又快又省又稳定；
- 复杂生成任务（实验提取/报告/问答）保持默认思考，质量优先。
**通用知识**：换模型时要重审所有调用点——推理模型的 token 经济与普通模型完全不同，「max_tokens 截断」的失败形态从「输出一半」变成了「输出为空」。

## 其它踩坑与决策

1. **宽 `except Exception` 的代价显形**：`_relevance_scores` 因漏导入 `parse_json_reply` 抛 NameError，被预筛的降级 except 吞掉走「纯引用数」路径——测试断言失败才暴露。教训：**降级路径要留痕**（测试要断言走了预期路径），否则降级机制会掩盖真实 bug。
2. **OpenAlex 政策变化**：开始返回 429「Insufficient budget」（免费预算制）。应对：config 填 `email` 进礼貌池（待用户决策）；架构上契约层 degraded 状态使此类变化不再伤及整体。
3. **cmd 管道喂中文不可行**（GBK 解码失败），chat 实测改用 Python subprocess + `PYTHONUTF8=1` 驱动。
4. **off_topic 边界**写入分类器 prompt：科研/技术概念相关一律接待（防误拒），启发式兜底路径不判 off_topic（宁可错接）。
