# M10 开发笔记 · 库管理自主权：预览筛选、分组、删除与上传

真实使用反馈驱动的里程碑，主题一句话：**检索的默认流程从「全自动替用户做」
改为「机器找，人挑选」**。

## 四项能力

**① 检索预览 + 挑选入库**：`/api/search` 改为纯预览（不写库），返回候选清单，
库内已有的条目带 `duplicate_of` 标记并禁选；`POST /api/papers/ingest` 接收
用户勾选的候选与分组名。服务层拆成两层：`search_sources`（检索+校验+标记，
只读）与 `ingest_papers`（入库，重复项幂等合并元数据）；原 `search_and_ingest`
变成组合函数，CLI 与对话助手的全自动模式行为不变。前端弹层支持全选新的、
逐条勾选、命名分组后入库。

**② 分组导航**：papers 表加 `tag` 列（老库 PRAGMA 检测后 ALTER 迁移）。
标签在入库时写入：Web 检索用用户命名的分组名、流水线用检索主题、上传固定
「本地上传」；已有条目不被覆盖。前端新增「分组」chips 行（数量统计 +
按组过滤），详情页与论文行显示所属分组。这回应的是「论文平铺一列没法看」——
检索来源（对话历史里的主题）成了浏览的主线索。

**③ 删除**：`DELETE /api/papers/{sid}`，全链清理——账本记录、向量库块、
原文/解析/知识产物目录一并移除。设计原则：留一半状态会产生「幽灵论文」
（检索得到但问答没有、详情打不开），所以要么全删要么不删。

**④ 上传**：`POST /api/papers/upload`（multipart，50MB 上限，格式白名单），
内容哈希幂等（与 `pa add` 同一实现，下沉到 `services/library_ops.py`），
状态直达 downloaded，之后即可「一键处理」。上传按钮在检索工具栏。

## 验收中抓到的缺陷

- 预览响应最初没带 `pdf_urls`——照此入库的论文将永远无法下载全文。验收
  脚本核对字段时暴露，已在预览序列化中补齐。教训：**两段式 API 的响应必须
  携带下一段所需的全部字段**，「预览」不只是展示。
- 删除验收时发现按标签过滤 + 删除 + 分组计数联动全部正确；分组数量随删除
  自动减少（计数来自实时查询，非冗余存储）。

## 验收

- pytest 109 → 112（预览不写库、入库打标、tags 统计、删除、上传幂等、
  非法格式 400）；
- 真实服务端到端：检索 24 条候选（4 条已标记库内已有）→ 入库 3 篇带标签 →
  分组导航/过滤正确 → 删除后 404；上传 DOCX stub 首次 201/重复 is_new=false/
  非法格式 400；
- 截图验收：检索源选择、上传按钮、分组 chips、行内分组标注全部渲染正确。
